# credentials-d v0.1.0

The first public release of credentials-d.

## What you can build with it

Use one small credential API to save passwords, API tokens, refresh tokens and
similar secrets without putting them in ordinary configuration files.

v0.1.0 provides:

- `LinuxCredentialStore` for Linux desktop applications;
- `WindowsCredentialStore` for Windows applications;
- `MacOSCredentialStore` for macOS applications;
- `EncryptedCredentialVault` when you want a portable application-controlled
  vault file;
- optional security-key unlock for encrypted vaults;
- `MemoryCredentialStore` for tests and temporary credentials.

The common workflow is:

```d
CredentialHandle handle;

auto status = store.save(secret, handle);

status = store.withSecret(
    handle,
    (scope const(ubyte)[] bytes) @safe
    {
        // Use the credential here.
    }
);

status = store.update(handle, replacement);
status = store.remove(handle);
```

`CredentialHandle` and `VaultUnlockMethod` are non-secret opaque values that
can be persisted in normal application settings.

## Documentation

Start with the README and the three buildable examples:

- `examples/basic-store`
- `examples/encrypted-vault`
- `examples/security-key-vault`

Generated Ddoc/DDOX documentation shows only the supported consumer-facing API;
implementation modules under `credentials.backend.*` are not part of the
compatibility contract.

## Platform qualification

Linux, Windows, encrypted-vault and the tested physical security-key paths have
qualification coverage.

The macOS backend is compiled and fail-closed tested in CI. Final production
qualification still requires a properly signed/provisioned macOS application
context.

## Compiler baseline

- DMD 2.111.0
- LDC 1.41.0

The release gate additionally checks DMD 2.111.0–2.113.0 and LDC 1.41.0–1.43.0.
